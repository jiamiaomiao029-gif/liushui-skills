# 大规模材料处理协议

适用于材料超过约100条、跨多个文件、跨一年以上，或单次无法可靠完整读取的情况。目标不是假装“读完了一切”，而是让结论可追溯到覆盖范围、事件样本和反例。

## 1. 开始前确认边界

先记录：

- 材料类型、文件数或条目数、可见时间范围；
- 本轮是否允许保存事件索引、是否允许保留原话；
- 明显缺失的年份、平台、附件或私密情境；
- 最终输出是仅供当事人查看，还是可能公开使用。

分析授权不等于公开授权。原始日记、聊天记录和第三方信息默认不进入对外版本。

## 2. 分批建立事件索引

按时间段、来源或可处理批次读取。每批先记录事件，不直接定性人格。

| 批次 | 覆盖范围 | 已读条目/文件 | 事件数 | 初步模式 | 反例/异常 | 未覆盖部分 |
|---|---|---:|---:|---|---|---|
|  |  |  |  |  |  |  |

每个事件至少保留：日期或位置、触发、实际反应、代价或反馈、最短必要原话/定位信息、隐私级别。

## 3. 跨批次归纳

只有在模式跨时间或跨情境重复出现时，才从事件升级为人物结论。对每条结论同时寻找：

- 支持它的独立事件；
- 不能被它解释的事件；
- 只在特定场景成立的边界；
- 可能来自公开内容经营而非稳定反应的部分。

## 4. 交付时声明覆盖度

所有人物结论必须附以下信息：

- **覆盖范围**：已读材料的时间、来源和数量；
- **支持证据**：至少列出对应事件或索引位置；
- **反例/边界**：哪些材料削弱或限制了结论；
- **成熟度**：已证实模式／较强假设／弱线索；
- **未覆盖风险**：哪些未读材料可能推翻当前判断。

未完成全量阅读时，不得使用“完整人格画像”“已看完全部材料”或同等含义的表述。

## 5. 停止条件

出现以下任一情况时，先交付阶段性索引和当前假设，而不是继续假装深读：

- 已覆盖的材料足以支持稳定模式，继续读取的边际价值低；
- 关键年份或来源缺失，无法判断跨时间稳定性；
- 材料量超过当前工具可可靠处理的范围；
- 用户未授权继续读取，或材料出现不宜处理的第三方隐私。

阶段性结果必须写清：已覆盖什么、尚未覆盖什么、下一批最值得读取什么。
