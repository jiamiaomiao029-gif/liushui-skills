# 人设考古

从一个人已经活过、说过和做过的事情中发现人物，而不是替他发明一套讨喜标签。

## 先判断材料形态

- 用户提供了朋友圈、旧文案、社交媒体记录、日记或访谈：进入**材料考古**，完整读取 [references/material-analysis.md](references/material-analysis.md)。材料超过约100条、跨多个文件或跨一年以上时，同时执行 [references/large-material-protocol.md](references/large-material-protocol.md)。
- 用户没有足够材料，希望通过聊天回忆经历：进入**对话考古**，完整读取 [references/dialogue-interview.md](references/dialogue-interview.md)。
- 两者都有：先分析已有材料，只对证据缺口进行对话追问，避免重复提问。
- 用户已经有初步人物结论，只想寻找或改写事件：直接使用“人设事件单元”，无需从头访谈。

## 核心原则

### 人设是可预测的反应

人设不是观众知道“这个人善良、专业、有执行力”，而是观众大致知道：这个人遇到某类事情时，会怎么反应。

优先寻找：

- 反复做出的选择；
- 面对机会、风险、失败、金钱、关系和学习时的默认反应；
- 跨时间或跨场景仍然出现的行为模式；
- 稳定的语言、癖好、兴奋点、愤怒点与较真之处；
- 看似冲突、实际上由同一套逻辑连接的两种倾向。

### 证据先于结论

证据强度通常按以下顺序递减：

1. 当时留下的具体行为、原话、选择与结果；
2. 跨时间、跨情境重复出现的反应；
3. 后来对过去经历的回述；
4. 他人评价；
5. 当事人的抽象自我介绍。

自我介绍可以作为待验证线索，不能直接当作人物结论。一次行为只能形成假设；有重复证据或反例检验后，才升级为稳定模式。

### 人设靠事件完成

不要写“我很有执行力”。找到一次具体触发，呈现这个人当时看见了什么、做了什么选择、付出什么代价、得到什么现实反馈。

不要为了让故事完整而补造经历、数字、原话、客户反馈或心理活动。材料缺失时，明确标为“待补事实”。

## 人设事件单元

每个候选事件至少整理出：

- **触发**：什么具体事情发生了；
- **默认路径**：普通人或过去的自己通常会怎么处理；
- **人物反应**：当事人实际做了什么；
- **冲突与代价**：这次选择和什么发生碰撞，付出了什么；
- **现实反馈**：结果、失败、意外或尚未验证；
- **人物证据**：它证明了哪一种稳定反应；
- **原始依据**：对应的原话、日期、材料位置或访谈回答。

当两个人的关系需要被塑造时，优先寻找“同一件事进入两个人手里，他们分别怎么反应”，不要直接介绍关系。

## 从事件到人物模型

在证据足够时，尝试提炼一台人物发动机：

> 某种触发或欲望 → 默认行动方式 → 内在约束或质量控制 → 现实反馈 → 下一次行动

人物发动机不是固定公式，也不要求必须有三个词。只保留能解释多件事、也允许预测未来反应的部分。

同时区分：

- **职业或商业定位**：这个人能帮谁解决什么问题；
- **人物母题**：这个人长期在追求、对抗或解决什么；
- **行为机制**：他遇到事情通常怎么行动；
- **人物张力**：哪两种看似矛盾的倾向同时存在；
- **表达素材**：哪些真实事件能让观众自己看见以上结论。

职业标签不能代替人物，人物故事也不能代替清晰的专业价值。

## 输出

根据证据成熟度交付，不为了显得完整而强行定型。默认包括：

1. **研究边界**：分析了什么、时间范围多长、缺少什么；
2. **稳定人物模式**：每条都附行为证据和可能的反例；
3. **人物发动机**：能解释多件事的行动循环；
4. **人物张力**：由事件支持的矛盾组合；
5. **人设事件库**：按“事件—反应—代价—反馈—人物判断”整理；
6. **待验证假设**：证据不足但值得继续观察的线索；
7. **可公开边界**：哪些事件可直接讲、需匿名化、只保留机制或不宜公开。

如果用户只要求一项，例如“帮我找三个人设事件”，只交付当前所需部分。

## 脱敏与隐私

- Skill 本身不内置任何具体个人的经历、学历、职业、口头禅或结论。
- 输出公开内容前，默认提醒并处理第三方姓名、联系方式、单位、住址、精确交易数据、未公开关系与可识别细节。
- 脱敏不等于抹掉事件。可以替换身份、模糊时间和数字，但要保留触发、选择、冲突与反馈，否则人物证据会消失。
- 不擅自读取用户未提供或未授权的私人账号与文件。

## 质量检查

完成前检查：

- 删除姓名和简介后，这个人的反应还有辨识度吗？
- 结论来自事件，还是来自当事人自称？
- 是否把一次偶然行为夸大成稳定性格？
- 是否主动寻找了反例，而不是只挑支持材料？
- 是否把复杂人物写成“真诚、专业、执行力强”的通用好词？
- 观众最终是被告知他是什么人，还是亲眼看见他做了一件只有他会这样处理的事？

## 与 liushui-ip 协作（可选）

仅当用户另行要求 IP 定位时，按 [references/persona-to-ip-brief.md](references/persona-to-ip-brief.md) 输出一份脱敏的「人物—定位输入简报」，再作为 `liushui-ip` 的「能力/人物证据」输入。不要把人物性格直接等同于市场需求，也不要默认转交完整日记或敏感原文。单独安装本 Skill 不影响人设考古功能。
